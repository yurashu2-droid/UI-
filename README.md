# UI RAID Studio

既存のゲームをViteの開発プロジェクトに分割したものです。画面・ゲームデータ・戦闘ルール・保存形式は元のHTMLを引き継いでいます。

最新の仕様・試作の範囲・未確認事項は [開発チェックポイント](DEVELOPMENT_CHECKPOINT.md) を参照してください。通常戦闘はcombat-v4、一時サーバー負荷は明示的に選ぶ実験室限定の試作です。

## 起動

Node.js 22.12以降を使用します。依存関係の復元には次を実行してください。

```sh
npm ci
npm run dev:local
```

`dev:local` は画面用Vite（5178）とローカル対戦サービス（5180）を同時に起動し、対戦サービスの応答をVite経由でも確認してから `UI RAID local ready` と表示します。Ctrl+Cで、このコマンドが起動した2サービスを終了します。サービスが終了・起動失敗した場合も、もう片方を残しません。既にどちらかのポートが使われている場合は停止し、既存プロセスを再利用・終了しません。

画面だけなら従来どおり `npm run dev`。個別に動かす場合は別のターミナルで `npm run arena` と `npm run dev` を使えます。対戦データの `ARENA_STORE` 指定は引き継ぎますが、`dev:local` の `ARENA_PORT` はViteの接続先と同じ5180に限ります。公開サービスへの配備やログインは不要です。サービス準備完了は対戦相手の存在を保証しません。

ブラウザで http://127.0.0.1:5178/ を開きます。ポートは保存先が意図せず変わらないよう固定しています。`dev:local` は5178/5180固定です。既存のこのプロジェクトのサーバーを利用する場合やポートを変更する場合は個別起動を使い、`vite.config.ts` のポート・proxyと `ARENA_PORT` を明示的に合わせてください。

分割後の `index.html` はダブルクリックせず、開発サーバーから開きます。従来の単一ファイル `UI_RAID_STUDIO.html` は、比較用として無変更で残しています。

### TypeScriptの適用範囲

ゲーム本体の9モジュール、起動点、Vite設定、シミュレーションをすべてTypeScriptにしています。`strict: true` / `allowJs: false` でゲーム本体も型チェックの対象です。戦闘イベントと取引結果は種類・成功状態で型を区別し、DOM・編集状態・音声・Canvasにも型を付けています。読み込んだJSONは `unknown` として受け取り、保存データ検証後に使用します。

ソース内の `.js` import指定はES Modulesの出力形式に合わせたものです。開発・ビルド時はVite/TypeScript、テスト時はtsxが対応する `.ts` ソースへ解決します。元HTMLは回帰比較用の固定資料で、現在のアプリからは読み込んでいません。

## セーブを引き継ぐ

保存キー `ui-raid-studio-v3-` とJSON形式は維持しています。ただし、以前の `file://`、別ブラウザ、別ポート、`localhost` と `127.0.0.1` の間ではブラウザ保存領域が異なります。

1. 以前使っていたブラウザで元HTMLを開く。
2. メニューの「JSONを書き出す」で保存する。
3. 新しい画面のメニューの「JSONを読み込む」で取り込む。

ランと実験室のセーブは別々なので、必要なモードごとに書き出してください。初回チュートリアルの完了フラグはブラウザ保存領域ごとです。

### 回収した外観も別の端末へ移す

構成JSONだけでは、個人コレクションの取得外観一式は移りません。物語JSONに含まれる最大8件の解析キャッシュも、コレクション全体の代わりではありません。

1. 移動元の「個人コレクション」で「取得外観を書き出す」を選び、別のJSONファイルとして保存します。
2. 移動先の「個人コレクション」で「取得外観を読み込む」を選び、追加・同一・競合の件数を確認します。空のコレクションでも利用できます。
3. 「追加して復元」で保存します。通常の構成や物語のJSONは、それぞれ従来の「読み込む」で別に読み込みます。

外観の復元は追加専用で、同一の保存済み取得物は増やさず、競合があれば全体を中止します。進行・資金・手持ち・未受取のURLレイド報酬を移す操作ではなく、外部へ送信やURLの再取得もしません。持ち運べるファイルは取得物256件・取得データ256件・UTF-8で16MiBまで。上限超過や不整合は、省略せず書き出し・復元を拒否します。これはコレクション自体の保存件数制限ではありません。ファイルは署名されておらず、ハッシュ検証は内容の整合性を確認するもので、実際の勝利の証明ではありません。


## ローカルHTMLから外観を回収する（実験室限定）

1. 実験室で自分のページの編集画面を開き、メニューの「URLレイド」を選びます。
2. 「HTMLファイル」でUTF-8の`.html`または`.htm`を一つ選びます。必要なら「CSSファイル（任意）」も一つ選びます。HTMLは512 KiBまで、選択CSSは256 KiBまでで、有効な埋込styleと選択CSSの合計も256 KiBまでです。
3. 「ローカルHTMLを近似再構成」を押します。ファイル選択だけでは解析しません。CSSは`site.css`のような半角英数字で始まる英数字・`._-`と小文字`.css`の名前に限り、HTMLの有効なlinkがその名前または`./site.css`を一度だけ参照する必要があります。URL・別パス・重複linkは拒否します。ファイル名の照合だけを行い、実際のフォルダーを調べることはありません。CSSを外す時は「CSSなしに戻す」を使います。
4. 近似配置を確認し、「このページに挑戦」から勝利後、UIを一つ選んで外観を回収します。選択・解析だけでは報酬は増えません。途中で閉じた未受取のローカル報酬は実験室で再開してください。
5. 敗北後に配置を見直す時は「自分のページを編集して再戦」で閉じ、編集後にURLレイドの「前のローカル近似を再開」を選びます。同じタブ・同じ実験室の近似一つだけを一時保持し、ファイルを読み直さず再挑戦できます。自動再開はせず、未受取の勝利があればそちらを優先します。

「一時保持だけを消去」は戻るための近似だけを消し、表示中の相手や回収済み外観は変更しません。この一時保持に元ファイル・生HTML/CSSは入れず、ページ再読込や別ラン・保存先への切替では使えなくなります。通常のセーブや外観バックアップにも含めません。

解析はこの端末のWorkerで行い、読込を含む5秒で期限切れになります。「ローカル読込を中止」、再選択や画面切替で古い解析は無効になり、失敗時も選択中の相手と報酬は残ります。中止後にネイティブの読込自体が終わっても、その結果から解析・選択を再開しません。元HTML/CSSを表示DOMへ挿入せず、元JavaScript・iframe・画像・フォント・追加CSSを実行／取得したり、ファイルを外部へ送ったりしません。フォルダーやZIPには対応しません。

対応する静的見出し・リンク・購入UIなどと限定CSSを使ったゲーム用の近似です。JavaScriptだけのアプリ、任意のdiv/canvas画面、元ページと同じレイアウトは再現できず、元HTMLとの比較もありません。ローカル由来はHTMLハッシュで識別し、ファイル名・ファイルシステムのパス・生ソースは保存しません。近似に使った文字・色は回収する外観に含まれます。

物語の解析・エネルギーや旧遠征の対戦・回収には使えません。回収済みの外観は既存のコレクション／外観適用規則とバックアップで扱えますが、本編・オンラインの入手経路は増えません。新しい`local-file`取得元種別に対応していない旧版は、この取得物を読み込めません。外観JSONの形式・上限や従来の公開ページ・付属ページの保存内容は変えません。詳細は [開発チェックポイント](DEVELOPMENT_CHECKPOINT.md) と [取得・解析の仕様](server/site-ingest/README.md#local-htmlcss-import-separate-laboratory-only-boundary) を参照してください。実ブラウザのファイル選択・操作・読み上げ・見た目の受け入れ確認は未実施です。

### 配置比較と作業場のUI取引

実験室のSIDECHANNELで元の4部品の配置を保ち、パンくずだけを選ぶと、選択欄の「履歴の上へ（15%加速）」「PDFの上へ（15%加速）」で移動できます。元のパンくずだけを通常のUndo/Redo付きで動かし、編集ラベルや外観は残します。他の部品・所持数・寸法などを変更すると比較は使えません。自動対戦や配置リセットはせず、復元量や勝敗は相手と発動時刻で変わります。

物語の「UI棚」から「UIの取引を開く」を選ぶと、最小化した巡回先ウィンドウも元の位置・大きさで表示します。

## 次の追加変更：ローカルのラベル・ノート・相性表

ローカルHTMLの近似では、チェックボックスを囲むlabelに加え、同じ解析ツリーの`input type="checkbox"`のIDを`label for="..."`で正確に指定した文字も取り込みます。重複ID・隠れた／inertな要素・対象の衝突などは保守的に除外し、フォームの入力値やARIAの名前を代わりに使いません。parse5が修復した実際のHTMLツリーを判断する限定対応で、ブラウザの読み上げ名計算全体を再現するものではありません。公開URLの解析と従来の有効な内包labelの記録は維持します。[詳しい対応範囲](server/site-ingest/README.md#next-increment-explicit-local-checkbox-labels)を参照してください。

27番目のテンプレート・41番目の実験室対戦相手に、Notionをモチーフにした独自の「LEAFNOTE」を末尾追加します。通常部品4個・額面$14・CPU4・占有28,832px²の配置比較です。左の2本目の青リンクだけを`(24,240)`から`(24,520)`へ動かすと、縦ナビの15%加速を失う代わりに、ページ全体で先頭2本へ配る余白の強調が本文リンクへ移ります。ノート・目次・下段の棚は固定表示で、内包・外部共有・同期はしません。

双方HP10,000・CPU12・設備なしの24秒の限定測定では、空の相手へのダメージは342→322.5、既存の429が一つある相手へは138→142.5。ただし6.7秒の429例は両方38で、開始時刻や観測時間で変わります。両配置とも、3リンクすべてに文字強化をつなぐ同額$14・CPU4の構成に両席で敗れます。429への対策や普通のショップで完成できる経路を保証するものではありません。[配置・測定条件と公式のモチーフ資料](src/catalog/README.md#next-increment-leafnote-notebook-template)を参照してください。

### 構成例図鑑の相性表

実験室の「構成例図鑑・相性表」を開くと、必要な計算コードを読み込み、従来と同じ実エンジンの240試合を少しずつ計算します。完了した試合数を進捗欄に表示し、「計算を中止」で止め、「計算を再試行」で最初からやり直せます。計算そのものの失敗も再試行できます。コードの読込失敗時は「画面をもう一度読み込む」を選んでください。

「閉じる」・Escape・別の画面への切替でも古い計算を無効にし、遅い結果で閉じた画面を戻しません。表の勝敗・並び順・条件は維持し、両者HP440・CPU56・管理画面4枠（各自の設備）の比較であることを明示します。通常プレイの初期処理能力や入手条件を保証する表ではありません。

計算は1回の処理を最大4試合または約8msで区切る協調的な方式です。1試合自体は途中で分割しないため8msを超える場合があり、総計算時間の短縮や実ブラウザの応答速度を保証しません。ゲームの進行・資金・保存は変更しません。実際のブラウザ・Tab操作・読み上げ・見た目の確認は引き続き未実施です。

## 検証・ビルド

```sh
npm test                  # 元HTMLとの比較、20通りの戦闘、進行・保存互換性
npm run typecheck         # ゲーム本体・設定・シミュレーションすべての型チェック
npm run simulate          # 全プリセット × 5対戦相手の結果を表で表示
npm run simulate -- --json
npm run build             # 型チェックと dist/ の生成
npm run preview           # http://127.0.0.1:4173/ でビルド結果を確認
```

Windows PowerShellでnpmへのオプション転送がうまくいかない場合、JSON出力は `node node_modules/tsx/dist/cli.mjs scripts/simulate.ts --json` でも実行できます。

`dist/` はクライアントの配布用成果物です。静的HTTPサーバーでオフライン機能を配信できますが、URL解析と非同期オンラインには別途APIサービスが必要です。相対アセットパスにしているため、後からElectronに組み込める構成です。Electronおよび固有名詞の置き換えは今回の変更には含めていません。

戦闘比較テストは移行時の基準として元HTMLを読みます。今後ゲームバランスを意図的に変える場合は、比較テストの期待値・基準もその変更に合わせて見直してください。
