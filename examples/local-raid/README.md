# ローカルレイドの小さな見本

「こもれび文具室」は、このリポジトリ用に作った架空の文具ページです。実験室のローカル取り込みに使うファイルは、このフォルダーの **`example.html` と `example.css` の2個**です。HTMLの文字コードはUTF-8で、CSS参照は一つだけ、正確に `href="./example.css"` です。

## 試す手順

1. [本体の起動手順](../../README.md#起動)でUI RAIDを開きます。この見本用のサービス・アカウント・配備は不要です。
2. メニューから「実験室」を選び、自分のページの編集画面でメニューの「URLレイド」を開きます。物語や通常の対戦ではローカル取り込みを使えません。
3. 「HTMLファイル」で `examples/local-raid/example.html` を一つ選びます。
4. 「CSSファイル（任意）」で `examples/local-raid/example.css` を一つ選びます。HTMLとCSSは別々の欄で選び、名前を変更しないでください。フォルダー・ZIP・このREADMEは選びません。
5. 「ローカルHTMLを近似再構成」を押します。**ファイルを選ぶだけでは解析・対戦・報酬獲得は行われません。**
6. 下記の6部品と「コード解析による近似配置」の表示を確認します。「このページに挑戦」で実際に勝利した後、表示されたUIを一つ選ぶと、その近似外観を回収できます。解析の成功は勝利を保証しません。

読み込みを止める時は「ローカル読込を中止」。CSSなしを比べる時は「CSSなしに戻す」を押してから再構成します。HTMLだけでも同じ6部品を選びますが、色や枠線などの外観は変わります。ファイル名の一致エラーが出たら、選んだCSSが `example.css` か、HTMLの参照が `./example.css` のままか確認してください。取り込みはファイル名だけを照合し、フォルダーを検索しません。

## 期待する結果と範囲

現在の解析器では、候補6個をすべて選び、960×680のゲーム用画面に2列・3段で配置します。見出し・本文・操作の元の位置や寸法を測ったものではありません。`sourceRect` はすべて `null` で、解析結果は `code-approximation` / `inferred-flow` / `low` です。

ソース順の部品は次のとおりです。

1. 「こもれび文具室」：見出し → `ab_heading`
2. 「紙のたより」：ナビリンク → `ab_nav`
3. 「この見本について」：ナビリンク → `ab_nav`
4. 「文具を探す 検索（見本）」：検索フォーム → `go_search`
5. 「紙の手ざわりを楽しむ」：チェックボックスのラベル → `gov_check`
6. 「便せんをカートに追加（見本）」：購入ボタン → `am_buy`

チェックボックスとラベルは別々の兄弟要素です。`input id="paper-texture" type="checkbox"` と `label for="paper-texture"` の正確な対応から、ラベルの文字を取り込みます。入力値やARIA名を部品名として使いません。

この見本は見出し・検索・チェック・購入の非ナビ候補をちょうど4個に抑えています。購入ボタンを囲む `article` は置いていません。現在の解析器で商品用配置に切り替わると、検索やチェックが選ばれなくなるためです。見出しやボタンを増やせば、すべてが回収候補になるとは限りません。

CSSは既存の限定対応だけを使います。単純なタグ・クラス・子孫セレクター、16進色、端末の汎用フォント、範囲内のpx文字サイズ・余白、太字、中央寄せ、単色の枠線と角丸です。元のレイアウトをコピーするものではなく、対応する文字・色などからゲーム用の配置を合成します。長い文字や余白はゲーム内に収まるよう調整されることがあります。

## 通信・保存について

- ソースにJavaScript、画像、動画、外部フォント、外部リンク、CSSの追加読み込みはありません。CSSファイル一つ以外の参照はページ内の移動先だけです
- 検索と購入は表示用で、実際の検索・注文・決済はできません。フォームは `method="dialog"`、ボタンはすべて `type="button"` で、送信先や入力値は設定していません
- 元ファイルをゲームのDOMに挿入せず、選んだバイト列を端末内のWorkerで解析します。ファイルをアップロードしたり、参照先のCSSや素材をネットワークから取りに行ったりしません
- HTMLは512 KiB、CSSは埋込分と選択分を合わせて256 KiBまでです。読み込み開始から5秒の期限があります。この見本は両方とも上限を大きく下回ります
- HTML/CSSのSHA-256で入力内容の整合性を記録します。ファイル名・ファイルシステムのパス・生HTML/CSSは取得データに保存しません。見本のタイトル・ラベル・限定した色や構造情報は近似外観に含まれます
- 選択やハッシュ一致は勝利の証明ではありません。回収には実験室での実際の勝利と、その後のUI選択が必要です

## 検証

リポジトリのルートで、対象だけを検証できます。

```sh
node --import tsx --test tests/local-import-example.test.mjs
```

実ファイルを解析して、6部品の意味・配置・外観、元バイト列のハッシュ、取得データの検証、CSSなしの取り込み、スクリプトや外部リソースの不在を確認します。**実ブラウザでのファイル選択、操作、読み上げ、見た目は未確認です。** 対応するブラウザ経路は `ERR_BLOCKED_BY_CLIENT` で止まっており、このテストはブラウザ受け入れ確認の代わりにはなりません。

詳細は[取得・解析の仕様](../../server/site-ingest/README.md#local-htmlcss-import-separate-laboratory-only-boundary)を参照してください。

## フォーム外の検索欄を比べる見本

別の小さな見本 [native-search.html](native-search.html) は、架空の「こもれび資料室」です。これはHTML一つだけで使います。「HTMLファイル」にこのファイルを選び、前のCSSが選択中なら「CSSなしに戻す」を押してから再構成してください。必要な限定CSSはHTML内にあります。元の `example.html` / `example.css` の内容は変えていません。

現在の対応では、候補5個をすべて選びます。

1. 「こもれび資料室」：見出し
2. 緑色の「検索」：`<search>` 内の二つの明示的な検索入力を、一つの検索領域として近似
3. 薄紫色の「検索」：フォーム外の独立した `input type="search"`
4. 「紙の資料だけ」：チェックボックス
5. 「この見本の読み方」：ページ内リンク

検索は既存の `go_search` を使い、どちらも一般名「検索」です。欄の周りのラベル、placeholder、入力値を検索名へコピーしません。領域側は `<search>` 自体の色、独立した入力はそのinputの色を使います。限定CSSの対応規則は6件で、元の画面のレイアウト・複数入力欄・検索処理を再現するものではありません。

フォームのないネイティブ検索の追加対応を示すサンプルです。通常の `input type="text"` を自動で検索にしたり、任意のARIAウィジェットを対応扱いにはしません。旧版では検索2個が候補にならない場合があります。元ファイルのJavaScript・外部素材・送信先はなく、回収は実験室で勝利した後に明示的に選びます。ブラウザの見た目や実ファイル選択の受け入れ確認は未実施です。
